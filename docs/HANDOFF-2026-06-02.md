## 3. Key Conventions (Do Not Deviate)

### Button colours
Every action button across the entire frontend uses **`btn-primary-edulearn`** (dark navy). Never use `btn-primary`, `btn-outline-primary`, or `btn-link` for action buttons. `btn-outline-secondary` is fine for Cancel/back-only UI.

### Modal pattern
All modals **must** be rendered via `ModalPortal` component (`src/components/ModalPortal.jsx`). Do NOT render modals inside the page `<div>` — the page root has a CSS animation `transform` that becomes the containing block for `position:fixed`, clipping the modal footer off-screen on short viewports.

```jsx
import ModalPortal from '../../components/ModalPortal';
// ...
{showModal && (
    <ModalPortal>
        <div className="modal-backdrop fade show"></div>
        <div className="modal fade show d-block" tabIndex="-1">
            ...
        </div>
    </ModalPortal>
)}
```

When a `<form>` wraps `modal-body` + `modal-footer`, pass flex through explicitly so Bootstrap's scrollable modal still works:

```jsx
<div className="modal-content" style={{ maxHeight: '90vh', display: 'flex', flexDirection: 'column' }}>
    <form style={{ display: 'flex', flexDirection: 'column', flex: 1, overflow: 'hidden' }}>
        <div className="modal-body" style={{ overflowY: 'auto', flex: 1 }}>
```

### No JSON textarea/input fields
**All JSON fields must be replaced with structured UI.** Zero raw JSON inputs are acceptable. See Section 5 for the complete mapping of what was changed.

### Read-only locked fields
Pattern: `readOnly` + `bg-light` + `cursor: 'not-allowed'` style.

```jsx
<input
    className="form-control bg-light"
    style={{ cursor: 'not-allowed' }}
    readOnly
    value={someValue}
/>
```

### Cross-component state sync (no Redux)
Use browser custom events:

```js
// Dispatch (e.g. in NotificationsPage after marking read)
window.dispatchEvent(new CustomEvent('notifications:read'));

// Listen (e.g. in Navbar to refresh badge)
window.addEventListener('notifications:read', fetchUnread);
```

### Notification pattern (backend)
Notifications are **best-effort** — always wrap in `try { } catch { }` so they never fail the main request. Fan-out loops are fine at current data scale.

### Back/Forward cache guard
`main.jsx` has a `pageshow` listener that forces `window.location.reload()` on `event.persisted === true`. This prevents bfcache restoring a stale logged-in/out page. **Do not remove it.**

### Number input scroll guard
`main.jsx` also blurs `<input type="number">` on `wheel` events. This prevents accidental value changes when scrolling past a focused number field. **Do not remove it.**

```
            mcp__plugin_chrome-devtools-mcp_chrome-devtools__evaluate_script,
            mcp__plugin_chrome-devtools-mcp_chrome-devtools__wait_for,
            mcp__plugin_chrome-devtools-mcp_chrome-devtools__take_screenshot
```

Workflow:
1. `list_pages` to see open tabs
2. `navigate_page` to `http://localhost:5173`
3. `take_snapshot` to get UID-annotated DOM (use `evaluate_script` for cheaper factual reads)
4. `fill` or `click` using element UIDs from snapshot
5. `list_network_requests` to verify API calls + status codes

**Prefer `take_snapshot` over `take_screenshot`** — snapshot gives element UIDs you can use for subsequent interactions; screenshots are just images.
