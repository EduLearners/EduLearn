## 2. Bugs fixed and VERIFIED in the browser

| # | Bug (reported) | Root cause | Fix | Verified live |
|---|----------------|-----------|-----|---------------|
| B-1 | Any logged-in user could open another role's page by typing the URL / using Back (e.g. Student reaching the admin **Users** screen) | 37 of 40 routes had **no** frontend role gate | Central `config/routeRoles.js` + `RoleGuardedOutlet` rendered in `AppLayout` | ✅ Student→`/users`, Finance→`/reports` = **Access Denied**; Auditor→`/reports` = renders |
| B-2 | After admin logout → student login → **Back**, the previous admin page (and data) was restored | Browser **bfcache** restored the painted page without re-running React/guards; logout used push navigation | `pageshow`/`persisted` reload in `main.jsx` + `navigate('/login', { replace:true })` in `Navbar.jsx` | ✅ Reproduced exact scenario (Auditor `/reports` → switch to Student → Back) = **Access Denied, no data leak** |

**Also confirmed still-correct (Phase 1 re-verification):**
- Case-sensitive login — `Registrar` → 401, `registrar` → 200.
- Generic auth errors — 401/403 bodies carry **no stack trace or route info**.
- Student form Gender includes **"Prefer not to say"**.

## 5. Key knowledge gained (don't re-learn this on Monday)

- **Source of truth for authorization = the PRD** (`docs/EduLearn-PRD-v1.0_2.docx` §6) + `docs/PRD-DISCREPANCIES.md`, cross-checked against controller `[Authorize]` and the policies in `Program.cs`. **Do not assume role rules — verify.**
- **Policy map** (from `Program.cs`): `AdminPolicy`=ITAdmin · `DeptAdminPolicy`=DeptAdmin,ITAdmin · `FinancePolicy`=Finance,ITAdmin · `CourseManagerPolicy`=Instructor,DeptAdmin,ITAdmin · `EnrollmentPolicy`=Student,Registrar,ITAdmin · `UserViewPolicy`=ITAdmin,Registrar,DeptAdmin · `AuditViewPolicy`=Auditor,ITAdmin. `POST /submissions` = **Student only** (caller must be the student).
- **Term format:** `^20[0-3]\d-(Spring|Summer|Fall|Winter)$` → e.g. `2026-Fall` (NOT "Fall 2026").
- **Seed/term mismatch (N-1):** the seed creates operational rows in **2026-Fall** but the app's current term is **2026-Spring**, so term-scoped dashboard counts (Instructor "My Sections", Registrar "Sections") read 0. Non-term views show the data. Fix on Monday by seeding in the current term (or both).
- **Frontend session keys:** `localStorage` `jwt` / `role` / `username` (see `authService.saveSession`).
- **Harness pitfalls now handled:** never attach a body to GET/HEAD (fetch throws → misleading "HTTP 0"); throttle bursts + retry-once or the dev server drops connections.
- **Environment constraints:** Python is **not** available; **no package installs** (no Playwright/Vitest). Testing is via the Claude preview browser + PowerShell only.
